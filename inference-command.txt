  Notes:
  - --from_image_embed takes the folder; prefix it with the literal keywords prompts_only,
    ignore_negative_prompt, and/or prompt_only_and_all_settings (any order) to switch modes.
  - ignore_negative_prompt discards the metadata negative so it falls back to --pre_prompt_neg / blank.
  - Global defaults (--image_size H W, --infer_steps, --guidance_scale, --flow_shift, --seed, --sampler,
    --scheduler) are the prompt-only values AND the per-image fallbacks in full-settings mode.
    --image_size is HEIGHT WIDTH. er_sde/beta57 are now the built-in defaults, so --sampler/--scheduler
    are optional unless overriding.
  - Sampler/Scheduler are pulled from metadata only when they map to a script choice (euler/er_sde,
    default/beta57); A1111 values like "Euler a" or "Karras" don't map and fall back.
  - --seed accepts -1 (or omit it) for a random seed.
  - --images_per_prompt 4 -> 4 seed-incremented variations per prompt (seed, seed+1, ...).
  - --prompt_count 10 caps to the first 10 USABLE prompts (PNGs with no positive prompt are skipped and
    do not count). --prompt_count_skip_first 4 skips the first 4 usable prompts first, for pagination.
    Both apply to --from_folder / --from_file / --from_image_embed.
  - In full-settings mode a metadata value overrides the matching global default per-image; settings
    mode needs BOTH Steps and CFG in the metadata, otherwise that image reverts to prompts-only.

    
    

  LORA A/B TESTER (--lora_test_folder):
    Sweep a folder of LoRAs against a fixed generation set so you can compare them apples-to-apples.
    For EACH top-level .safetensors in the folder (subfolders ignored), the whole otherwise-configured
    run is repeated with that one test LoRA added on top of your fixed --lora_list/--lora_weight LoRAs.
    Works with every mode (--from_file / --from_folder / --from_image_embed / single --prompt), so total
    images = (number of test LoRAs) x (images the run would produce otherwise).

      --lora_test_folder <folder> [multiplier]     multiplier applies to each test LoRA (default 1.0)

    Trigger words: if a "<loraname>.txt" sits next to a test LoRA, its text is injected into the prompt
    AFTER your --pre_prompt and BEFORE the main prompt (i.e. it carries that LoRA's trigger keywords).
    No .txt = no injection.

    Each image's settings sidecar (.txt) additionally records "source_image:" and "test_lora:" so you can
    always tell which LoRA (and at what multiplier) produced a given image.

    Note: LoRAs are merged into the model at load time, so the models RELOAD once per test LoRA (not per
    image). Incompatible with --interactive and --latent_path.

    Example (test every LoRA in a folder at 0.9 against a PNG-metadata prompt set):
    uv run sd-scripts/anima_minimal_inference.py \
        --dit  .../anima-base-v1.0.safetensors \
        --vae  .../qwen_image_vae.safetensors \
        --text_encoder .../qwen_3_06b_base.safetensors \
        --lora_list  .../div2k_anima_v1-step00000360.safetensors 1.0 \
        --lora_test_folder /media/aikenyon/WDRed16TB/models/loras/_totest 0.9 \
        --from_image_embed prompts_only /media/aikenyon/WDRed16TB/sd/source_content/prompt_source \
        --image_size 1216 832 --infer_steps 50 --guidance_scale 3.5 --flow_shift 2.0 --seed 42 \
        --prompt_count 4 \
        --save_path ./anima_out --output_type images \
        --sampler er_sde --scheduler beta57
